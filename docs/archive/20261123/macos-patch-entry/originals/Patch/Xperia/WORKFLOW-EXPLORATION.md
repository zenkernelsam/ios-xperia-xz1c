# 高效率探索方法论（从 lilac→iOS GUI 项目提炼）

> 适用场景：在**资料稀缺、硬件不可随意重刷、每次实验都要等机器重启**的平台上，
> 把"玄学"变成"可重复的工程"。本文是与具体设备无关的部分；设备相关的
> 历史细节看 `AGENTS.md`，外部分支情报看 `RESEARCH-FRONTIER.md`。
> 目标读者：未来接手 Y700 或任何新板子的自己/队友。

---

## 0. 一句话总结

**用最便宜的可观测性，锁定唯一的变量，换来确定的事实。**
每一轮只回答一个问题；回答不了就换观测通道，而不是靠猜。

---

## 1. 三角框架：目标 / 红线 / 证据

任何一步决策都先过这三关：

1. **目标**：成功必须是**可观测的外部状态**（"屏幕出现 hello"），
   不是"代码写完了"。把目标拆成能单独验证的里程碑（根挂载→launchd→
   SpringBoard→WindowServer→上屏）。
2. **红线**：先列不可逆操作，再开工。例：UFS 写入、ICE 配置、SD 卡擦写、
   分区覆写、固件刷写。**红线内的动作一律先确认、后执行、留回滚。**
3. **证据**：任何结论必须能指向一条日志/一次 dump/一张照片。
   没有证据的"应该"视为噪声。

这三者冲突时：红线 > 目标 > 速度。绕过红线省下的十分钟，
往往要用一整晚恢复数据来还。

---

## 2. 观测阶梯：从最便宜的开始

按成本从低到高排队，**永远先用当前能用的最低层**：

| 层 | 通道 | 成本 | 适用 |
|---|---|---|---|
| L0 | 屏幕控制台 / 远程相机截图 | 秒级 | 启动早期、panic 横幅、UI 状态 |
| L1 | 内核 printf + panic 横幅寄存器 | 一次重启 | 早期崩溃、异常现场 |
| L2 | 固定物理地址环形日志（exec ring）、DDR cell | 一次重启 + dump | 无法在屏上停留的信息 |
| L3 | 整卷/整内存离线 dump + fsck + 块级 diff | 分钟~小时 | 文件系统、用户态崩溃、历史状态 |
| L4 | 参考实现源码重建 + 二进制比对 | 一次性投入 | 驱动移植、常量测绘 |

原则：

- **能读寄存器就不要加 printf，能 printf 就不要 dump 16GB。**
- L2/L3 的证据可能被复位清掉（DDR 不可靠），重要结论要在**同一次启动**
  里多通道冗余记录。
- 观测本身可能改变系统（加日志改时序、读未上电的总线会挂死）。
  所以：**先只读、后写；先探测、后上电。**

### 远程相机感知环

没有 adb/ssh 时，屏幕就是唯一输出。固定流程：

1. 相机不要自动对焦（手动对焦），避免启动瞬间糊掉。
2. `frame.jpg` 僵死时改用 MJPEG：先 `/override`，再拉
   `/video?1280x720`，在字节流里**先找最后一个 EOI、再往前找 SOI** 抽帧。
3. 关键帧立刻落盘并命名（版本号+步骤），不要只留在内存里。

## 3. 最小变量迭代（执行论核心）

每一轮实验写成固定格式：

```
假设：<一句话>
改动：<只改一个变量，版本号 vNNN，脚本化>
观测：<用哪条通道，预期看到什么>
结果：<原始证据>
结论：<证实/证伪；下一步>
```

铁律：

- **一轮一个变量。** 同时改两个，失败后无法归因。
- **改动脚本化、幂等、带断言。** 源码改动用 `patch_vNNN_*.py`
  （`assert count == 1`），二进制改动用独立脚本；禁止手改后忘记。
- **版本化工件。** 内核 `k02xx`、payload `vNNN`、镜像 `shim-*` 一一对应；
  任何时候能回答"现在手机里跑的是哪一版"。
- **快速证伪。** 方向错了立刻回退（例：显示朝向误判，做了一轮
  xf 转置实验，用户一句"第一次是正常的"就全量回退）。沉没成本不是证据。
- **失败也是事实。** 记录"这条通道不可用"（IMEM 加扰读回乱码、
  DDR 复位后不可靠）本身就是资产，避免下次重复投入。

## 4. 风险工程：把不可逆操作变成可逆

- **数据面与元数据面分离**：能改文件内容就绝不改 HFS 元数据；
  补丁必须**同长度**（键名替换、入口桩），避免触碰 B-tree/日志。
- **禁止"旧 dump 的元数据块回写到已运行卷"**。块级混写 = 目录损坏，
  这个坑付过一整晚的代价。
- **整卷一致流程**：要装新文件/改元数据 → 离线改整卷 → fsck →
  整卷回刷（字节级 md5 对齐），不做局部块写。
- **每次改动前留证据**：`git status`、备份原文件、记录 md5。
- **复位不是关机**：PSHOLD=0 是断电；WDT/PSCI 复位会保留/破坏什么，
  要单独验证。
- **危险动作前停三秒**：这条命令失败，最坏会失去什么？有没有只读替代？

## 5. 无人值守闭环（把"等人按键"变成"自动下一轮"）

目标：**一条命令完成 编译→打包→进 fastboot→启动→取屏→判定→下一轮**。

关键构件：

1. **可重复进入 bootloader**：`adb reboot bootloader`（Android 可用时），
   否则用已验证的按键/复位路径。
2. **启动器运行时补丁**：每次新 fastboot 会话先打（本项目为 xperable
   `-B -U -s ... -x -4 -6`），补丁复位即失效，必须脚本化。
3. **失败自动回 fastboot**：利用 PMIC 软复位原因寄存器
   （本项目 `0x88f=0x06` BOOTLOADER），panic/WDT 都自动回来；
   必要时用 `RET=1` 在加载前武装。
4. **取屏自动化**：相机抽帧 + 简单判定（关键词/亮度/区域），或串口日志。
5. **超时与分段**：单次工具调用不要 sleep 超过 ~6 分钟（会被截断）；
   长等待拆成多次轮询，或用后台任务 + 完成通知。

无人值守只用于**只读/可复位**实验；任何写盘、刷写仍走人工确认。

## 6. 离线取证：当系统不给你日志

适用：mount 失败、用户态崩溃、迁移卡死、元数据损坏。

流程：

1. **整卷拉取**（只读）：`dd if=/dev/block/... bs=4M`；
   记录分区、大小、md5。能挂载就挂载，不能挂载就让 7-Zip/hdiutil 直接读。
2. **只读修复副本**：`fsck_hfs -y -f /dev/diskN` 只对 dump 副本做；
   修复前后块级 diff，通常只有卷头/日志头变化。
3. **崩溃日志优先于猜**：crash log 的 stackshot、超时时间、进程名
   往往直接给出根因（例：DataMigrator 10 分钟超时）。
4. **定位到文件偏移 → 卷偏移 → 块号**：建立换算表，所有补丁写进脚本。
5. **用数据面补丁绕过**：能改 plist 键名/桩函数，就不要删文件/改目录。

## 7. 借力：参考实现考古

新驱动不要从零写，先找"同一个内核、同一类硬件"的已完成移植。

- **重建参考树**：clean worktree + 完整补丁系列（本项目 sailfish 187 个
  补丁）；不要在东拼西凑的树上读代码。
- **做差异表**：基址、时钟、电源、固件、PAS id、SMMU、SoC 版本特性。
  逐项列出"相同/不同/未知"，未知项先做只读探测。
- **移植顺序固定**：只读探测 → 上电/时钟 → 复位释放 → 固件加载 →
  自检 → 用户态 ABI → 真正业务。每一级都能单独失败、单独回归。
- **复用已验证子系统**：触摸抄同 SoC 已验证的 QUP/RMI 状态机；
  不要重新发明时序。
- **并行侦察**：把"查资料/读参考树/列差异"交给子代理并行做，
  主线只保留结论；但**结论要自己抽查**（读关键文件确认）。

## 8. 构建与资源预算

- **增量构建**优先（本项目 ~4 分钟）；只有结构变更才全量。
- **机器码级改动直接二进制 patch**（秒级），源码改动才重编。
- **宿主资源限制**：ES/异常 CPU 机器上，重负载统一
  `taskset -c 0-13 nice -n10 ionice -c2 -n7`，避免整机重启。
- **磁盘预算**：大 dump 用完即删；注意 APFS 快照可能延迟释放；
  保留"可再生"清单，别在 99% 满的盘上做构建。
- **并行工具调用**：互不依赖的读/查/构建可以同批发出；
  有依赖的必须串行（例如先确认产物路径再打包）。

## 9. 记忆与交接（上下文会满，人会睡）

- `AGENTS.md` 是**权威状态**：当前状态、红线、最近里程碑、下一步。
  每完成一个里程碑立刻写，不攒着。
- 长任务在 compact 前必须写清三件事：**已完成/进行中/待办**，
  以及"下一个最小实验"。
- 文档分层：`AGENTS.md`（状态）→ `HANDOVER-*.md`（专题）→
  `RESEARCH-FRONTIER.md`（外部情报）→ 本文（方法论）。
- 给未来的人写"为什么"，不只是"是什么"；尤其记录**踩过的坑和红线**。

## 10. 常见反模式（都踩过）

| 反模式 | 后果 | 替代 |
|---|---|---|
| 一次改多个变量 | 无法归因，越调越乱 | 一轮一个变量 |
| 用旧 dump 的元数据块回写活卷 | 文件系统损坏 | data-only + 同长度补丁 |
| 相信相机/截图的"方向直觉" | 误判旋转，白做实验 | 用已知参照物（文字/图标）验证 |
| 在未上电的总线上读寄存器 | 总线挂死/复位 | 先电源/时钟，再 MMIO |
| 把 DDR 当可靠日志 | 复位后垃圾数据误导 | 同启动多通道冗余 |
| 长时间 `sleep` 等结果 | 工具调用截断，丢输出 | 分段轮询/后台任务 |
| 手改二进制不脚本化 | 无法复现、版本错乱 | 每版一个 patch 脚本 |
| 目标模糊（"让它能跑"） | 永远不算完成 | 可观测的成功判据 |

## 11. 迁移到新设备（以 Y700 为例）的启动清单

> 不假设具体 SoC 版本；按"先观测、后写入"的顺序推进。

1. **资产盘点**：SoC/平台、bootloader 解锁状态、分区表、原厂固件包、
   DTB/ADT、屏幕参数、触摸控制器、电源管理芯片、GPU。
2. **恢复通道**：先确认能稳定进 fastboot/EDL、能回刷原厂；
   没有恢复通道不开始。
3. **只读侦察**：`fastboot boot` 一个最小镜像（shim/TWRP），
   验证加载地址、DTB 传递、串口/屏幕输出。
4. **观测通道**：早期控制台 → panic 横幅 → 固定物理地址环形日志 →
   整卷 dump。先让"能看见"成立。
5. **根介质**：优先可回滚介质（ramdisk/SD），再考虑内部 userdata；
   任何写入前备份并确认红线。
6. **逐级点亮**：时钟/电源 → 存储 → 输入 → 显示 → GPU。
   每级都保留只读探测级（boot-arg 分级，如 `sweetgpu=1..8`）。
7. **参考移植**：找同 SoC/同平台已完成项目，做差异表，按固定顺序移植。
8. **闭环自动化**：启动器补丁、失败自动回 bootloader、远程取屏、
   版本化工件。
9. **文档化**：每步写进 `AGENTS.md`，红线单独成节。

## 12. 判定"这一轮是否值得"

开工前问三个问题：

1. 这轮能**新增一个事实**吗？（不能就换问题）
2. 失败时**最坏损失**是什么？可逆吗？
3. 有没有**更便宜的观测通道**能先回答它？

三个都过关再动手。效率不是跑得快，而是**少跑无效的圈**。
